## 同一月營收訊息能增加哪些證據

| 方法 | 對獨立證據的影響 | 代價及前視偏誤 |
|---|---|---|
| 延長同市場歷史，或向前累積新月份 | 每完整年度最多新增 12 次原規格的檢定機會 | 必須有當時可得的營收版本、公告時間、下市股票與可比行情；用今天存活名單或修訂後營收回填過去會前視。制度與成本改變也削弱固定效果假設。可核實的快取以外未列入容量。 |
| 增加使用同定義且同頻率披露的市場 | 當地新公告落在新的實際日期，才可能增加日期群；同日公告只擴大同一群。不同日期仍可能受同一全球衝擊 | 事前固定市場、換匯時點、基準、交易成本與當地可成交時刻；以 UTC 對齊資訊，並檢查跨市場及跨期相關。季報市場不能直接算成月訊號。合併後的結論適用於擴大後的市場母體。 |
| 按可查證的公司實際公告日分批 | 同樣的營收內容可在不同真實事件日首次可交易；同一公告僅計一次。相對原統一截止日，這是需要另登錄的執行設計 | 需逐公司原始公告時間、盤後及休市對齊、當時已發布的比較資料；不能用事後完整月份的橫截面排名決定較早批次的入場。不同日期或重疊持有期不保證獨立。 |
| 改為每日重讀同一公告、平移每月檢查日、或延長檢查間隔 | 前兩者無新增資訊事件；降低頻率可能降低重疊，也同時減少名義群數 | 只有事前定義且當時可取得的不同新公告可增加候選群數。按回測結果挑間隔會增加比較次數。 |

## HOLDOUT 與使用方式

凍結訊號研究起點至末筆可用行情日 **2022-01-01 至 2026-11-20**，共 1,785 個日曆日。前 1,428 日為開發期，後 357 日 **2025-11-29 至 2026-11-20** 標為 HOLDOUT，首個交易日 2025-12-01。行情暖機期不進分母。原全期分群報告與 v3/v4 舊樣本外報告已用到此區間，因此它只能防止進一步調參污染。真正從未見過的驗證需要事前凍結後新增的觀察。

受信任的發布端執行 `python scripts/research_partition.py export-train NEW_DIRECTORY`，從固定 Git 版本讀取三份逐筆帳本，只輸出三個 CSV。訊號在開發期但最晚出場落入 HOLDOUT 的整組排除。全部原有狀態保留，含缺價交易。實際開發匯出 v2 2,693、A-track 3,956、v3 1,776 列。只將 training-ledgers 工件交付研究環境。這個介面支援三份既有訊號帳本的研究；如需新的原始欄位，須由發布端先證實在當時可知並裁切，不可掛載整個 data 目錄。

新增研究在 [登錄表](experiments.md) 登記，門檻欄以 `dev ` 或 `final ` 開頭，檔案為 `experiments/new-K.py`。Frozen TW research 的 dev 工作只把已登錄的程式與訓練 CSV 掛入唯讀、無網路的容器。無 repo、歷史報告或 GitHub token。舊全樣本腳本與完整 checkout 屬發布端，持有完整 repo 讀權的人仍能直接看舊報告；若要對人員強制隔離，只能給去識別權限的開發端這份訓練工件，不能同時授予原倉庫讀權。

final 僅接受 main 上已審查提交與 final 登錄。經 research-final 環境執行時，先在指定遠端原子建立固定的 consumed tag 綁定提交，再產生 HOLDOUT 輸入並執行。重試會因 ref 已存在失敗，即使第一次計算中斷也不得重跑。保留 tag；維護者可在 GitHub 設定它的刪除保護及 research-final 的必要審查者。此變更只提交分支，未執行 final、未消耗保留樣本。研究紀律需搭配維護端的權限分離。
